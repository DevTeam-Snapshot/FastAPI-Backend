V2 모델 서버 연동 계약 변경사항

안녕하세요.
광고 기획 질문 구조 변경에 따라 백엔드의 V2 proto 계약을 확장했습니다.


1. 최종 질문 순서

lodging_type
→ lodging_information
→ selling_points
→ lodging_service
→ mood
→ color_preference
→ target_audience
→ ad_copy
→ complete

color_preference도 mood와 분리된 독립적인 질문 단계입니다.


2. brief 구조 변경

lodging_service 필드가 추가됐습니다.

- selling_points: 객실, 전망, 공간, 시설 등 공간 중심 특징 목록
- lodging_service: 무료 조식, 픽업, 할인 등 서비스·혜택 목록
- 두 필드 모두 문자열 배열이며 최대 5개입니다.

예시:

{
  "lodging_type": "hotel",
  "lodging_type_detail": null,
  "lodging_name": "스냅샷 호텔",
  "location": "부산광역시 해운대구",
  "selling_points": [
    "객실에서 보이는 바다 전망",
    "넓고 쾌적한 객실"
  ],
  "lodging_service": [
    "무료 조식",
    "해변 픽업 서비스"
  ],
  "mood": "밝고 시원한 여름 분위기",
  "color_preference": "파란색과 흰색",
  "target_audience": "커플 여행객",
  "ad_copy": "파도와 함께 시작하는 특별한 하루"
}


3. proto 변경사항

기존 필드 번호는 변경하지 않고 새 번호만 추가했습니다.

PlanningStep:
- PLANNING_STEP_LODGING_SERVICE = 8
- PLANNING_STEP_COLOR_PREFERENCE = 9

BriefField:
- BRIEF_FIELD_LODGING_SERVICE = 11

AdvertisementBrief:
- repeated string lodging_service = 10

BriefPatch:
- StringListReplacement lodging_service = 10


4. 모델 처리 요청사항

- lodging_service 단계에서 서비스·혜택 답변을 검증해 주세요.
- 유효한 답변은 BriefPatch.lodging_service로 전체 목록을 반환해 주세요.
- selling_points와 lodging_service를 서로 다른 정보로 판단해 주세요.
- 초안 생성 시 room은 selling_points의 공간 특징을 중심으로 사용해 주세요.
- 초안 생성 시 benefit은 lodging_service의 서비스·혜택을 중심으로 사용해 주세요.
- color_preference를 mood와 분리된 독립 단계로 처리해 주세요.
- 모델 측에서도 변경된 proto를 반영한 뒤 gRPC Stub을 다시 생성해 주세요.


5. 이미지 초안 규격

- 응답 형식: PNG
- 출력 크기: 1080 × 1350


6. 백엔드 반영 상태

- PostgreSQL planning_sessions.lodging_service JSONB 칼럼 추가 완료
- REST 요청·응답 스키마 반영 완료
- 기획 대화 gRPC 변환 및 BriefPatch 해석 반영 완료
- 초안 이미지 생성 gRPC 요청 반영 완료
- Python gRPC Stub 재생성 완료

모델 측 proto와 질문 진행 로직 반영이 완료되면 동일한 proto를 기준으로 연동 테스트를 진행하면 됩니다.
